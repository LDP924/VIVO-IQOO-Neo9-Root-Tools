【与 ReSukiSU 时代的差异】(踩过的坑)
  - 版本公式无 +700 偏移: ReSukiSU = 30000+commits+700, 原版 = 30000+commits。
  - ko 无 allow_shell 模块参数: `ksud insmod ko.ko allow_shell=1` 会直接失败,
    只能裸 insmod (DeployScript.ksuLoadCommand 已同步去掉)。
  - 原版 KSU init 会收掉加载后的同会话 root 脚本: vrpatch/sepolicy 必须在
    insmod 之前做 (GhostlockRunner.activateKsu 已按此顺序)。
  - 管理器安装不能走 exploit 域的 pm install ("Can't find service: package"),
    用 App 侧 PackageInstaller 会话免 root 唤起 (GhostlockRunner.promptInstallKsuManager)。
  - su_ksu (ReSukiSU 客户端) 与原版 ko 的 supercall/UAPI 不保证兼容; 部署后的
    root 授权走 KernelSU Manager (me.weishu.kernelsu)。
